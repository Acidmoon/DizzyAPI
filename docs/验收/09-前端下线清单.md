## 3. nginx 侧：端口不用改；`Origin` 两个值不同、必须按 location 分别设

### 3.1 现状（**第三版已由 `总工` 在 `<生产服务器>` 实测**）

| 路径 | 反代到 | `Host` | `Origin` |
|---|---|---|---|
| `/v1/*`、`/v1beta/*`、`/healthz` | gatewayd `127.0.0.1:18080` | — | — |
| `/api/*` | `api` 插件 `127.0.0.1:7791` | → `127.0.0.1:7791` | **`http://127.0.0.1:7791`** ✅ 生产已配 |
| 其余（含 `/`） | `web` 插件 `127.0.0.1:7792` | → `127.0.0.1:7792` | `/` → `https://127.0.0.1:7792` |

生产 `<站点域名>.conf` 里 `/api/*` 那个 location **已经**写着
`proxy_set_header Origin http://127.0.0.1:7791;`，与 `api` 的 `assertOrigin` 允许值一致
→ **切新 SPA 不会 403**。

### 3.2 结论

- **新插件监听 7792 已落地**（第一版的「只是设计目标」**已销账**）：
  `packages/dashboard/src/config.ts:38-41` 的 `DASHBOARD_DEFAULTS = { port: 7792, enabled: true }`，
  `packages/dashboard/src/service.ts` 据此 `listen(127.0.0.1, port)`。所以 3.1 那张表**一个字都不用改**，
  `Host` 改写值也一样（新插件的 `hostAllowed()` 只认 `127.0.0.1:<port>` / `localhost:<port>`
  + 配置里的 `extraAllowedHosts`，与 `web`/`api` 同一口径；不匹配回 **421**）。
- **但 `web` 必须先停**：两个插件同时 `listen(7792)` 时后者 `EADDRINUSE` **直接启动失败**
  （`packages/web/src/config.ts` 开头就写明「端口冲突直接失败，不静默换端口」；
  新插件 `static-server.ts` 的 `start()` 同样写死「不静默换端口」）。
  所以顺序只能是「先让新插件起来 → 再把 `web` 从 `app.yml` 摘掉 → 一次重启」，
  **不能**先关旧再上新（中间那段 502）。详见 [10-新前端部署清单](10-新前端部署清单.md) §3。
- **`Origin` 两个值不同，这才是要记住的事**（生产已经对，问题是**没人记过**）：
  - `/api/*`（7791）看 `api` 插件的 `assertOrigin`（`packages/api/src/http.ts:201-213`）：
    **精确字符串比对** `['http://127.0.0.1:<port>', 'http://localhost:<port>']`，`port` = 7791。
    协议写 `https`、端口写 7792、少写端口 → 全部 `403 API_ORIGIN_FORBIDDEN`。
    浏览器对**同源的 POST / PATCH / DELETE 也会带 `Origin`**（GET / HEAD 不带），
    而**新前端的写操作全在这条路上** —— 这是切换后才第一次真正触发该闸。
  - `/`（7792）看旧 `web` 的 `assertSameOrigin`（`packages/web/src/forms.ts:89-110`）：
    **比 host 不比协议**，所以 `https://127.0.0.1:7792` 只是历史口径。切换后 7792 是新
    `dashboard` 的**纯静态服务，根本不读 `Origin`** —— 这条留着无害、去掉也不影响。
  - **所以：`/api/*` 必须 `http://127.0.0.1:7791`，`/` 必须 `https://127.0.0.1:7792`。
    协议与端口都不同，必须按 location 分别设，一个全局值满足不了两处。**
- **但仓库里没有任何文档记录过 `/api/*` 这条**：`06-上线顺序.md` §10.3 与 `AGENTS.md` §6.3
  都只写了「`/` 要把 `Origin` 改写成 `https://127.0.0.1:7792`」。生产能跑是因为当初配 nginx
  时就按 location 分开写了，**不是有据可依** —— 换台机器照文档配就会踩。
  这条已补进 [10-新前端部署清单](10-新前端部署清单.md) §2.0/§2.2。
- **交叉印证**：`命令行` 线的 [11-cli-api-依赖清单.md](11-cli-api-依赖清单.md) §1 第 2 条
  **独立推出了同一件事**（原文「新 SPA 会发 `Origin`，所以 nginx 对 `/api/*` 也得改写
  —— 这条是给 `工具` / 部署线的」）。两条线互不相干地得出同一结论。
- 仓库里**没有 nginx 配置文件**（搜 `*.conf` / `nginx*` 零命中），宝塔那份只在服务器上。
  本版引用的生产配置由 `总工` ssh 上去核过，**不是我本地验证的**。

### 5.2 为什么这样对：它是「随旧前端下线」而不是「单独判它死刑」

三条支撑，都在代码里可查：

1. **零消费者**：真实消费者只有 `web`（`src/asset-version.ts:13,69`、`src/layout.ts:153,178,180`、

2. **模版已经自带字体，两套字体并存没有意义**：新前端用 `geist`（本地字体、构建不联网），
   中文走系统栈。再接一套得意黑要么覆盖 `--font-sans`、要么只给标题加 `font-heading`
   —— 那是**另开一套视觉规范**，与「按模版来」相反。
3. **合规上做减法，不是加法**（这条最容易搞反，见 §5.3）。

### 5.3 OFL 义务：**不再分发 → 不再触发「随分发附许可全文」**

- 得意黑是 SIL OFL-1.1。OFL 的「随分发保留 LICENSE 与版权声明」义务，**只在分发字体文件时成立**。
- 删包之后，仓库与产物里**都不再有这个字体文件**（`dist/` 里也不会有，因为新前端的构建
  不引用它），也就**不再有分发行为**，所以 `assets/LICENSE`（4 422 B）**不必带走**。
- **反面写法要避免**：不要写成「删包但要保留 OFL 全文」/「把 LICENSE 挪到新前端的 `public/`」。
  那是把**已经不存在的义务**当成存在，会误导下一个做部署的人去找一份根本不用的许可文件。
- **唯一还需要留意的**：仓库 git **历史**里仍有那份 woff2（删除是删文件，历史不重写）。
  这与「当前版本是否在分发」是两件事；若 owner 之后要求仓库可公开，再单独评估。

## 8. CSP：新旧两套，别混（owner 2026-10-31 拍板）

| | 旧 `web` | 新 `dashboard` |
|---|---|---|
| 出处 | `packages/web/src/service.ts:45-46` 的 `SECURITY_HEADERS` | `packages/dashboard/src/csp.ts` 的 `contentSecurityPolicy()` |
| `script-src` | `'self'`（零 inline，脚本全外链） | `'self' 'nonce-<每次随机>'`（内联 `<script>` 靠 nonce） |
| `style-src` | `'self'` | `'self'`（**`<style>` 元素仍受约束**） |
| `style-src-attr` | 无（不需要） | **`'unsafe-inline'`**（只放开 style 属性） |
| `img-src` | `'self' data: https:` | **`'self' data: blob:`**（不再允许任意 https 图床） |
| 其余 | `default-src 'self'` / `connect-src 'self'` / `frame-ancestors 'none'` / `base-uri 'self'` | 同左，另加 `font-src 'self'` / `object-src 'none'` / `form-action 'self'` |
| 其它安全头 | `X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy: no-referrer` | `nosniff`、`Referrer-Policy: no-referrer`、**`Cross-Origin-Opener-Policy: same-origin`**（没有 `X-Frame-Options`，靠 `frame-ancestors 'none'`） |

**为什么新前端必须放开 `style-src-attr`**：shadcn / Radix 的浮层定位、侧栏宽度
（`--sidebar-width`）、recharts 的 svg 尺寸全靠 React 的 `style={…}` 写进内联 style 属性；
`style-src 'self'` 会把它们全丢掉 —— 表现是侧栏宽度塌陷、弹窗定位错乱、图表尺寸 0。
owner 拍板「都按照模版来」，所以照上游原样接受，不自创更严的规则。

**两条边界，改的时候别越过**：
- **只放开属性、不放开 `<style>` 元素**：`style-src 'unsafe-inline'` 会连 `<style>` 一起放开，
  那是另一个量级，**不许**。
- **`script-src 'unsafe-inline'` / `'unsafe-eval'` 一律不许**，nonce 也不许固定成常量
  （固定 = 公开 = inline）。这两条在 `csp.ts` 的注释里写死了（「不接受的做法」那段）。

→ 所以「旧站的纯 `'self'` 随旧前端一起消失」是对的，**但不要把旧口径写进新前端的验收标准**。
新前端的验收口径见 [10-新前端部署清单](10-新前端部署清单.md) §5.1 第 10 条。
