## 3. nginx 侧：**理论上不用改，但有一条必须先做**

### 3.1 现状（出处：`docs/验收/06-上线顺序.md` §10.3，与 `AGENTS.md` §6.3 一致）

| 路径 | 反代到 |
|---|---|
| `/v1/*`、`/v1beta/*`、`/healthz` | gatewayd `127.0.0.1:18080` |
| `/api/*` | `api` 插件 `127.0.0.1:7791` |
| 其余（含 `/`） | `web` 插件 `127.0.0.1:7792`，且 **`Host` 改写成 `127.0.0.1:7792`**、`/` 还要把 `Origin` 改写成 `https://127.0.0.1:7792` |

### 3.2 结论

- **新插件如果监听 7792**，上面的表一个字都不用改（`Host` 改写值也一样）。
  > ⚠️ 「新插件监听 7792」目前**只是设计目标**：`界面`/`交互` 的 worktree 里我实测
  > **还没有** 7792 的实现（`packages/dashboard` 只有 `app/`，没有 `src/`，全仓搜 7792
  > 命中的都是旧 `packages/web/src/config.ts:20` 的 `WEB_DEFAULTS`）。
  > 这条要等骨架落地后**再确认一次**，别按「已经定了」写进部署步骤。
- **但 `web` 必须先停**：两个插件同时 `listen(7792)` 时后者 `EADDRINUSE` **直接启动失败**
  （`packages/web/src/config.ts` 开头就写明「端口冲突直接失败，不静默换端口」）。
  所以顺序只能是「先让新插件起来 → 再把 `web` 从 `app.yml` 摘掉 → 一次重启」，
  **不能**先关旧再上新（中间那段 502）。详见 [10-新前端部署清单](10-新前端部署清单.md) §3。
- 仓库里**没有 nginx 配置文件**（搜 `*.conf` / `nginx*` 零命中），宝塔那份只在服务器上。
  所以「nginx 不用改」这句话**只能在服务器上核实**，本地无法验证 —— 记为**未验证**。

## 5. 字体策略（`font-smiley`）：列选项，**不拍板**

### 5.1 现状（实测）

- 包名 `@dizzyapi/plugin-font-smiley`，服务名 `fontSmiley`，纯资源服务（不起 HTTP、不读写存储）。
- 字形：得意黑（Smiley Sans）v2.0.1 **子集** —— 全量 1.15 MB / 9497 字形 → **~508 KB / 4156 字形**，
  生成脚本 `packages/font-smiley/tools/build-subset.py`。
- 因 OFL 要求保留字体名、本站要改名，字体内部 name 表已改成 `Dizzy Sans`；
  版权 / 设计者 / 许可 / 许可 URL 等 name 记录原样保留，`LICENSE` 全文在 `packages/font-smiley/assets/`。
- 消费方式：**只有 `web` 用它** —— `@font-face` 被 `web` 追加进 `/assets/app.css`，
  字节从 `/assets/fonts/dizzy-sans.woff2` 发；`scope` 默认 `headings`，当前 `app.yml:314` 配的是 **`all`**。
- 许可证：SIL OFL-1.1（可自托管、可子集化、可改名，**必须随分发保留 LICENSE 与版权声明**）。

### 5.2 四个选项

| 方案 | 做法 | 影响 |
|---|---|---|
| **① 继续用（推荐）** | `font-smiley` 留着，新插件把它的 `@font-face` 注入自己的样式入口（Tailwind 的 `fontFamily` 指到它） | 零新工作；OFL 义务已经在履行；中文标题仍是得意黑，**这是产品的视觉锚点**，换掉等于换品牌 |
| ② 全交给 Tailwind 默认字体栈 | 删 `font-smiley`，`font-sans` 用系统字体栈 | 少 508 KB 下载、少一个插件；但**中文标题掉回系统黑体**，视觉直接退化，且 `build-subset.py` 那套子集流程作废 |
| ③ 交给 Tailwind 但保留字体文件 | 删插件、把 woff2 放进新前端的 `public/`，由 Tailwind 引 | 少一个插件（少 6 条用例、少一处端口/生命周期）；但字体的许可与子集化流程要挪到新包，`NOTICE` 也得跟着走 |
| ④ 只给标题用（回到 `scope: headings`） | 保留插件，`app.yml` 改 `scope` | 下载量不变（整个字体是一次性的），但不影响正文排版；**与 ⑤ 的实际差别只在 CSS 选择器** |

### 5.3 我的推荐：**①（保留插件，不动 `scope: all`）**

理由三条，都可查：
1. **它是唯一与「旧前端」解耦的包**：不起 HTTP、不依赖 `web`/`page-template`，
   删 `web` 不会让它坏。留着不需要任何改造。

### 6.2 会被删掉的「护栏」（要**先搬走再删包**，不能跟着一起没）

这几条不是「测旧前端」，而是**用旧前端的文件钉住业务规则**，删包时会静默失去保护：

| 护栏 | 位置 | 它钉的是什么 | 去处 |

| API 文档自证（三份） | `packages/web/test/pages-docs-{source,facts,http}.test.ts` | 文档里的入口 / 错误码 / 协议名必须真实存在 | 跟着 §4 方案 A 搬 |

### 6.3 不会变红、但要改名的（语义过期）

§2.4 的 7 个文件、19 行。**它们现在就是绿的，删完 `web` 仍然是绿的** ——
所以这批改动**不能用「测试红了」来发现**，必须照清单主动改。

### 6.4 会因为「改 `app.yml`」而红的？

**零**。全仓没有测试读真实 `app.yml`。搜 `app.yml` 只命中四类噪音：
`settings.test.ts:346` 用的是它自己 `mkdtemp` 造的夹具文件；
`admin.test.ts:7`、`catalog.test.ts:263`、`api/test/redeem.test.ts:231` 都只在**注释**里提到；
而且全仓**没有任何代码**用 `readFileSync` / `readFile` 去读真实 `app.yml`
（真实读取只发生在 cordis 的 Include 里，那是运行时装载，不是测试断言）。
所以改 `app.yml` 的白名单**不会**被测试挡住 ——
反过来说：**改漏了也没有测试会告诉你**，只能靠 §2.2 那张表逐条划。
