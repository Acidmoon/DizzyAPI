## 0. 准备

### 0.1 环境变量（先设好，后面每条都要用）

```bash
# 生产入口
export BASE="https://api.example.com"

# 本机直连两个回环端口（本地开发时用；生产要经 nginx）
export API="http://127.0.0.1:7791"     # api 插件：/api/*
export WEB="http://127.0.0.1:7792"     # web 插件：/console/* 与其余页面
export LLM="http://127.0.0.1:18080"    # gatewayd：/v1/* 与 /v1beta/*（生产由 nginx 反代）
```

**后面各册还会用到这些变量，用到时再填值（先知道它们是什么）**：

| 变量 | 是什么 | 从哪拿 |
|---|---|---|
| `KEY` | 测试用的 API key（`sk-…`） | 01 册 §1.3 创建时**只显示一次**，立刻存 |
| `REQID` | 某条请求的 reqId | 那条请求的响应头 `X-Request-Id` |
| `SESSION` | 普通用户的会话 cookie 值 | 浏览器 DevTools → Application → Cookies → `dizzyapi_session` |
| `A_SESSION` | A 用户的会话 cookie（越权回归用） | 同上，用 A 的浏览器会话 |
| `ADMIN_SESSION` | 管理员的会话 cookie | 同上，用管理员账号登录后复制 |
| `BREQID` | B 用户的某条记录 reqId | 用 B 自己的会话查一次（02 册 §3.2） |

> ⚠️ **会话 cookie 是秘密**：别提交、别贴到工单里、别写进 `~/.bash_history` 之外的共享文件。
> 它等同于「这个人的登录态」。

> ⚠️ **本地直连 api / web 时必须带对 Host**：`api` 与 `web` 都校验 `Host`
> （防 DNS rebinding），必须写成 `127.0.0.1:<端口>` 或 `localhost:<端口>`，
> 否则 **403 `API_HOST_FORBIDDEN`**（api）/ 页面报错（web）。
> 生产走 nginx 时 nginx 会把 `Host` 改写成回环地址，所以生产不用管这一条。

### 0.2 三种凭据，各管一条路（**别混**）

| 凭据 | 用在哪 | 怎么带 |
|---|---|---|
| **API key**（`sk-…`） | `/v1/*`（模型请求） | `Authorization: Bearer <API key>` |
| **会话 cookie**（`dizzyapi_session`） | `/api/*`（控制面） | `Cookie: dizzyapi_session=<token>` + **每个请求**都要带 `X-Requested-With: dizzyapi` |
| **网页登录** | `/console/*`、`/admin/*` | 浏览器登录后的 cookie |

> ⚠️ `/api/*` 的 `X-Requested-With: dizzyapi` 是**无条件要求**（登录前也要）。
> 少了它 → **403 `API_REQUEST_HEADER_REQUIRED`**。这与「有没有登录」是**两个独立开关**。
>
> ⚠️ `/v1/*` 与 `/api/*` **不是同一套鉴权**：`/v1/*` 认 API key，**不认**会话 cookie；
> `/api/*` 认会话 cookie，**不认** API key。

### 0.3 开工前先确认服务是活的

```bash
curl -sS -o /dev/null -w '%{http_code}\n' "$LLM/healthz"
```

- **对**：`200`
- **错**：`000`（连不上，gatewayd 没起）→ 先查 systemd：`systemctl status dizzyapi`

```bash
curl -sS -H "X-Requested-With: dizzyapi" "$API/api/health" | head -c 400
```

- **对**：200，JSON 里有 `"state":"ok"`（或 `"degraded"`）与 `components` 数组
- **错**：
  - `403 API_HOST_FORBIDDEN` → Host 头不对（见 §0.1）
  - `403 API_REQUEST_HEADER_REQUIRED` → 少了 `X-Requested-With`
  - `404` → 路径错了（健康检查在 `/api/health`，**不是** `/api/api/health`）

> `state` 有三档：`ok` / `degraded` / `down`。`degraded` 表示**某个插件不在运行**，
> 入口本身照常（这正是「缺服务只让对应路由 503」的设计）。要看哪个组件降级，
> 看 `components` 里每个 `{name, state, detail}`。

**出处**：`packages/api/src/http.ts`（`assertHost` / `assertOrigin` / `assertApiRequestHeader`）、
`internal/httpapi/server.go`（`mux.HandleFunc("/healthz", …)`）。
