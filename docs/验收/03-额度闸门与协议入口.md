## 4. 额度闸门：402 `INSUFFICIENT_BALANCE`

### 4.1 前提

闸门是 **pre 相位**判定，判完就拒：**不转发上游、不扣费**。
余额 ≤ 阈值（`-quota-min-balance-micros`，默认 0）就拒。

### 4.2 制造低余额

管理员把测试用户的余额调成 0（浏览器 `$WEB/admin/users` → 该用户「编辑」→ 余额调整，
或 `POST /api/users/<id>/balance`）：

```bash
curl -sS -X POST "$API/api/users/<测试用户id>/balance" \
  -H "Cookie: $ADMIN_SESSION" -H "X-Requested-With: dizzyapi" \
  -H "Content-Type: application/json" \
  -d '{"delta":"-100000000","reason":"验收：把余额打到阈值以下"}'
```

- **对**：200，`{"balanceMinor":"…"}`（金额是**十进制字符串**，整数微元）
- **错**：`400 API_BAD_REQUEST` → `delta` 必须是十进制整数字符串（**不经浮点**）

> ⚠️ 余额是**后付费**：可以扣成负数（记 `overdrawn`）。测试完记得调回来。

### 4.3 拿这把 key 发请求 → 必须 402

```bash
curl -sS -i "$LLM/v1/chat/completions" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"<对外模型名>","messages":[{"role":"user","content":"x"}]}'
```

- **对**：
  - HTTP `402`
  - `error.code = INSUFFICIENT_BALANCE`
  - `error.type = invalid_request_error`（402 落在默认分支）
  - **上游一次都没被打到**（看上游侧的访问日志；没上游时看 gatewayd 日志里没有该模型的请求）
- **错**：
  - `200` → 闸门没生效（余额快照没推过去？看 §4.4）
  - `503 QUOTA_SNAPSHOT_UNAVAILABLE` → 这是**严格模式**（`-quota-require-snapshot`）的行为，
    不是 402。默认模式（`false`）下快照不可用是**放行 + 告警**
  - `500` → 内部错误，回查 gatewayd 日志

### 4.4 闸门依赖心跳推送（这是最容易踩的坑）

余额快照是**心跳式**推送的（`quota` 插件默认 5 秒一轮，`pollIntervalMs: 5000`），
Go 侧按 TTL 判新鲜度。改完余额**最多等 5～10 秒**再测。

- **对**：等待后 402
- **错**：一直是 200 → 查 `quota` 插件是否在运行（`app.yml` 里 `enabled: true`）、
  桥是否通（`quota.status`）、TTL 与推送间隔是否匹配（**TTL 必须 ≥ 3 × 推送间隔**）。

> ⚠️ 2026-10-29 生产事故就是这个：**推送停了但请求照常 200**，余额已 −97 还在白用。
> 现在的护栏是「心跳式推送 + 告警 + 严格模式开关」，但**心跳断了就要有人看见**。

### 4.5 不可重试的含义

402 是**不可重试**的拒因：客户端应当**充值后再来**，而不是换一把 key 或无限重试。
所以重试同一请求只会再拿一次 402，**不会**打到上游。

**出处**：`modules/quotagate/stage.go`（`balance <= s.config.MinBalanceMicros` → 402）、
`contracts/quota.go`（`CodeInsufficientBalance`）、
`packages/api/src/errors.ts`（`_UNAVAILABLE|_NOT_READY` → 503 的兜底规则）。

## 5. `/v1/messages`（Anthropic 形状）与 Gemini 两个入口

### 5.1 Anthropic：`/v1/messages`

```bash
curl -sS -i "$LLM/v1/messages" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"<对外模型名>","max_tokens":64,"messages":[{"role":"user","content":"说一句话"}]}'
```

- **对**：
  - HTTP `200`
  - 响应体是 Anthropic 形状：`{"id":"…","type":"message","role":"assistant","content":[{"type":"text","text":"…"}],"usage":{…}}`
  - `usage` 里是 Anthropic 的键名（`input_tokens` / `output_tokens`）
- **错**：
  - `400 INVALID_REQUEST` → body 不是合法 JSON
  - 缺 `max_tokens` → **不报错**：网关会补默认值（`-anthropic-default-max-tokens`，默认 4096）
  - `404 MODEL_NOT_SERVED` → 模型没账号声明
  - **错误体形状是 Anthropic 的**：`{"type":"error","error":{"type":"…","message":"…","code":"…"}}`，
    `code` 是**纯增量**字段（老客户端看到的形状没变）

### 5.2 Gemini：`:generateContent`（非流式）

```bash
curl -sS -i "$LLM/v1beta/models/<对外模型名>:generateContent" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"role":"user","parts":[{"text":"说一句话"}]}]}'
```

- **对**：
  - HTTP `200`
  - Gemini 形状：`{"candidates":[{"content":{"parts":[{"text":"…"}]},"finishReason":"STOP"}],"usageMetadata":{…},"modelVersion":"…"}`
- **错**：
  - `404 NOT_FOUND` → 路径形状不对（**模型名在路径里**，body 里没有 `model`）
  - `400 INVALID_REQUEST` → 缺 model（路径解析失败时也会落到这里）
  - `403`/`402`/`429` → 与 [01-账号与模型请求.md](01-账号与模型请求.md) §2 同一套闸门

> **模型名可以带或不带 `models/` 前缀**，两种等价：
> `/v1beta/models/gemini-2.0-flash:generateContent` 与
> `/v1beta/models/models/gemini-2.0-flash:generateContent` 都对。
> **多层前缀或含其它斜杠一律 404**（防路径穿越）。

### 5.3 Gemini：`:streamGenerateContent`（流式）

```bash
curl -sS -N "$LLM/v1beta/models/<对外模型名>:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"role":"user","parts":[{"text":"数到十"}]}]}'
```

- **对**：
  - `data: {...}` 一帧一帧出来
  - **不发 `data: [DONE]`**：以最后一帧里的 `finishReason` 为准
  - 每帧是**完整的** `GenerateContentResponse`（累计形态，不是增量文本）
- **错**：
  - 一次性吐一个 JSON **数组** → **少了 `?alt=sse`**（这是最常见的错）
  - `404 NOT_FOUND` → 路径方法名拼错（必须是 `:streamGenerateContent`）

> Gemini 的 `usageMetadata.promptTokenCount` **含**缓存命中；网关按**上游协议**归一成四桶记账，
> 所以客户端看到的数与账本里的 `input` 桶**不一定相等**（这是已知口径，见 AGENTS.md §7「用量与价格」）。

### 5.4 跨协议转译抽查（有余力再做）

把账号声明成 `protocol: gemini` 或 `anthropic`，再用 OpenAI 形状的请求打：

- **对**：请求正常返回（网关在内部转译），用量照常落库
- **错**：`400 MODEL_NOT_SUPPORTED` → 账号协议不匹配且没有别的候选

**出处**：`internal/httpapi/server.go`（`mux.HandleFunc("/v1/messages", …)`、
`mux.HandleFunc("/v1beta/models/", s.handleGemini)`）、`internal/httpapi/gemini.go`
（`parseGeminiModelPath`）、`contracts/protocol.go`（三种错误体形状）。
