## 8. 管理台四页与价格页闸门三态

### 8.1 四页的共同判据

浏览器（管理员身份）依次打开：

| 页面 | 路径 | 对 | 错 |
|---|---|---|---|
| API key | `/console/api-keys` | 每行**只有**「复制 / 停用 / 编辑 / 删除」；编辑弹窗能改名称、过期时间、金额上限、并发数 | 行里还有别的按钮；编辑不生效 |
| 用户 | `/admin/users` | 每行**只有**「编辑」；弹窗里能改名称 / 角色 / 状态 / 余额 / 并发 | 余额不能改；并发数改不了 |
| 上游账号 | `/admin/accounts` | **筛选在上、账号列表在下**；点账号进详情页 | 顺序反了；详情打不开 |
| 操作审计 | `/admin/audit` | 每条写操作都在（动作码有中文标签，未映射的显式回退原始码）；能按动作 / 操作者 / 时间筛 | 审计是空的（但你刚做过写操作） |

**审计页为空但你刚改过东西** → 审计插件不在运行（页面会提示降级，但**写操作照常成功**，
审计是旁路）。这时先看 `app.yml` 的 `audit` entry 与 `adminPlugins` 白名单。

### 8.2 价格页的**闸门三态**（必须分清，不能含糊）

浏览器 `/admin/pricing`，看顶部那条提示：

| 闸门状态 | 页面必须显示 | 不能显示 |
|---|---|---|
| **关**（gatewayd 没开 `-pricing-gate`） | 「定价闸门当前是**关**的：未定价的模型现在**仍可请求**，费用按 0 计」 | 不能说「未定价不可请求」 |
| **开 + 快照健康** | 「定价闸门**已开启**：未定价的模型会被拒（403 `MODEL_NOT_PRICED`，不转发上游）」 | — |
| **开 + 快照没到 / 过期** | 「已开启，但网关还没收到价格快照（fail-closed）：所有模型都会被拒 503 `PRICING_SNAPSHOT_UNAVAILABLE`」 | 不能说「仍可请求」 |
| **读不到**（桥断 / 网关二进制过旧） | 「读不到网关的定价闸门状态：会不会被拒是**未知**，不是「一定放行」」 | **绝不能**说「仍可请求」 |

> ⚠️ **用 `null` 冒充 `false` 是另一种说谎**。读不到就明说「未知」。
> 这三态是 2026-10-30 明确的口径：闸门状态只增不改，桥读失败时**保留上一次已知状态**，
> 不退回 null。

### 8.3 定价闸门开着的实况（可选，会拒请求）

要真开闸门，得改 gatewayd 的启动参数 `-pricing-gate`（**默认关**），
并确认 `gate-feed` 在推价格快照（`app.yml` 里 `enabled: true`、`pollIntervalMs: 5000`）。

开着时请求一个**没配价**的模型：

- **对**：`403`，`error.code = MODEL_NOT_PRICED`，**不转发上游**
- **错**：`200`（闸门没生效）

### 8.4 未定价模型的处理

`/admin/pricing` 下半段「未定价的模型（闸门打开后会被拒）」：

- **对**：列出账号声明过但价格表里没有的模型，每行有「补价格」按钮；
  顶部还有「**添加模型**」按钮（`?add=1`）
- **错**：这个区块是空的（说明账号声明的模型都有价）；或没有「添加模型」按钮

### 8.5 key 级执行面（过期 / 金额上限 / 并发）都在真拦

给一把测试 key 设上限，然后在浏览器 `keys` 的「编辑」里改：

- **过期时间**：设成过去 → 用它请求 → **401 `API_KEY_EXPIRED`**
- **金额上限**：设成很小 → 用它请求到超限 → **402 `API_KEY_SPENDING_LIMIT`**
- **并发数**：设成 1，同时发 2 个 → 一个成功、一个 **429 `API_KEY_CONCURRENCY_LIMIT`**，
  且**请求结束后槽位归零**（再发一个能成功）
- 用户级并发（`/admin/users` 里设）→ **429 `USER_CONCURRENCY_LIMIT`**

**对**：以上四种都是**真拒绝**（不是只存着不生效）
**错**：设了上限还能一直用 → 闸门没接上（这是 owner 明确拍板要「真拦截」的）

### 8.6 管理面导出的 CSV（口径与用户面不同，多两列）

```bash
curl -sS "$API/api/admin/usage/export?range=7d" \
  -H "Cookie: $ADMIN_SESSION" -H "X-Requested-With: dizzyapi" | head -c 200
```

- **对**：表头是
  `time,user,api_key,model,input_tokens,output_tokens,cache_read_tokens,cache_write_tokens,total_tokens,cost_micros,status,duration_ms,client_ip,account`
  （比用户面多 `user` 与 `account` 两列）
- **错**：与用户面同 12 列 → 管理面把 `user` / `account` 丢了

**出处**：`packages/web/src/pages/admin_pricing.ts`（`renderGateState` 三态）、
`packages/api/src/views/usage.ts`（`adminUsageCsv` 的 14 列表头）、
`contracts/keygate.go`（四个稳定码）。

## 9. 内容审核：命中 block 规则必须 403 `CONTENT_BLOCKED`

### 9.1 前提：审核总开关默认是**关**的

`app.yml` 里 `content-audit` 的 `enabled: false`（新装的插件不该突然拦人）。
开着时规则照常保存，但推给网关的是「禁用 + 空规则」= 全放行。
**页面会明确提示这一点**，别把它当成「规则没生效的 bug」。

浏览器 `/admin/content-audit`：

- **对**：顶部提示「审核总开关是关闭的（配置 enabled=false）：规则照常保存，但推给网关的是「禁用 + 空规则」，等于全放行。」
- 要真拦人，得把 `enabled` 改成 `true`（改 `app.yml` 或用 settings 插件），**重启 dizzyapi**。

### 9.2 建一条 block 规则

在 `/admin/content-audit` 填关键词 → 「命中即拒绝（403）」→ 保存。

- **对**：规则出现在列表里（显示为脱敏片段），页面提示「已新增审核规则，并已推送到网关」
- **错**：报「规则 id 重复」→ 同关键词已有规则（409 `CONTENT_AUDIT_RULE_DUPLICATE`）

### 9.3 等推送周期，然后发一条命中的请求

推送是**心跳式**的（`pushIntervalMs: 5000`，5 秒一轮）。**等 5～10 秒**再测。

```bash
curl -sS -i "$LLM/v1/chat/completions" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"<对外模型名>","messages":[{"role":"user","content":"这里含有那个关键词"}]}'
```

- **对**：
  - HTTP `403`
  - `error.code = CONTENT_BLOCKED`
  - `error.type = authentication_error`（403 落在 OpenAI 的 `type` 映射里）
  - **上游一次都没被打到**
- **错**：
  - `200` → 规则没推过去：查 `contentaudit.status`（页面「Go 侧读不到 / 快照过期」提示会指出来）
  - `503 CONTENT_AUDIT_SNAPSHOT_UNAVAILABLE` → 那是**严格模式**
    （`-content-audit-require-snapshot`）的行为，不是 403
  - `500` → 内部错误

### 9.4 未命中的请求照常放行

同一条命令，换一个**不含**关键词的内容：

- **对**：`200`
- **错**：也被拒 → 规则匹配过宽

### 9.5 命中统计能看到

回到 `/admin/content-audit`，「按规则命中」区块：

- **对**：能看到刚才那条命中的记录
- **错**：区块空 / 提示「读不到 Go 侧状态」 → 桥断或网关二进制过旧

> ⚠️ 审核只做**大小写不敏感子串匹配**，**不做正则**（防 ReDoS）。
> 审计记录里**不放关键词本身**（那是管理面数据，不必扩散到审计表）。

**出处**：`contracts/contentaudit.go`（`CodeContentBlocked`）、
`modules/contentaudit/`（pre 相位闸门）、`packages/web/src/pages/admin_content_audit.ts`。
