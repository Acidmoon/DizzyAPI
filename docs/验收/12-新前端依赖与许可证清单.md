## 4. 逐个核「有雷的包」

### 4.1 `@fullcalendar/react` 7.1.3 —— **MIT（标准版），合规**
出处：<https://fullcalendar.io/license>（原文）与 registry `license: MIT`。
- **标准版**（非 premium 插件 + `fullcalendar` bundle）是 **MIT**，允许商用，条件是
  「all copyright headers are preserved」。
- **Premium**（`fullcalendar-scheduler` 与 premium 插件）是**商业许可 / 非商业 CC-BY-NC-ND /
  AGPLv3** 三选一 —— **我们绝不引入**。
- 上游只 import 了 `@fullcalendar/react`（2 个文件），依赖树里的 `core` / `daygrid` /
  `interaction` 也是 MIT（registry 实测）。
- **结论**：可用；但这两个文件属于「日历」演示屏，**计划删除**，所以最终不引入。

### 4.2 `d3-geo` 3.1.1 / `topojson-client` 3.1.0 —— **ISC，合规**
ISC 是宽松许可（等同 MIT 的简化写法），**不是 copyleft**。两者只被
`src/app/(main)/dashboard/logistics/_components/shipment-route-map.tsx` 一个文件用到
（物流地图演示），**随演示屏一起删**。

### 4.3 `simple-icons` 16.36.0 —— **CC0-1.0，但商标是另一回事**
出处：<https://github.com/simple-icons/simple-icons/blob/develop/DISCLAIMER.md>（原文）+
registry `license: CC0-1.0`。
- **代码/数据本体是 CC0**（公共领域，不强制署名）。
- **但图标是各家品牌的商标**：上游 DISCLAIMER 明确写「CC0 不代表所有图标都是 CC0」
  「用户需自行确认品牌指南」「Simple Icons 不对品牌方主张负责」。
- **对我们的含义**：拿它做「上游渠道 logo」（DeepSeek / OpenAI / Anthropic / Gemini 等）
  属于**指明服务来源的合理使用**，风险低；但**不要把品牌 logo 用作我们自己的产品标识或暗示背书**。
- **结论**：可保留，但要写进使用纪律。

### 4.4 `geist` 1.9.0 —— **SIL OFL-1.1**
registry `license: "SIL OPEN FONT LICENSE"`。OFL 允许**嵌入与随产品分发**，
但：① 必须随分发附 **OFL 全文**；② **字体本身不得单独售卖**；③ 若改字形集合
（子集化即 Modified Version），**必须改名**且**保留版权声明**。
> 我们已有一次同类实践：得意黑子集化 → 改名 `Dizzy Sans`、保留 `name` 表
> ID 0/9/13/14、保留 `LICENSE` 全文。新字体策略若用 Geist，照同一套动作做。
> 字体策略本身是 `优化` 线的交付物（待 owner 拍板），本文件只记合规动作。

### 4.5 `next` 16.4.3 —— **MIT + 商标限制**
代码 MIT。**商标**：Next.js / Vercel 商标由 Vercel 持有，其商标政策
（<https://vercel.com/legal/trademark-policy>）限制把 Next.js 名称或 logo 用作产品名、
或暗示官方背书。**我们的产品名是 DizzyAPI**，只作为技术栈使用 → 不构成问题。
唯一注意：**不要在页面版权/品牌区放 Next.js logo**。

### 4.6 `cn` 0.5.1 —— **MIT，是 shadcn 官方的 `cn()` 工具**
registry `repository: git+https://github.com/shadcn-ui/cn.git`。就是
`clsx + tailwind-merge` 的封装，被 **104 个文件** import，是维护成本最低的一个包。

### 4.7 `@base-ui/react` 与 `radix-ui` 并存 —— **两个都在，用途不同**
- `radix-ui`（36 处 import）：**绝大多数组件的基础**（dialog / select / dropdown / tabs /
  tooltip / sidebar / sheet … 共 30 个 ui 组件）。
- `@base-ui/react`（**只有 1 处**）：`src/components/ui/combobox.tsx`。
- **对 CSP / 运行时的影响**：两者都是纯客户端组件库，都**不需要内联脚本**，
  也不要求 `unsafe-eval`；`radix-ui` 的浮层用 CSS 定位 + inline style 属性（React 写的是
  `element.style`，即 CSSOM 赋值，**不受 `style-src` 限制**）。所以**不构成 CSP 风险**。
- **建议**：combobox 若不是必需，**删掉 `combobox.tsx` 从而不引 `@base-ui/react`**，
  把 UI 基础收敛到 radix 一家，减少一处风格分裂。

### 4.8 `shadcn` 与 `@shadcn/react` 是两个包，别混
- `shadcn` 4.23.0：**CLI**（`shadcn add` 那套）。`src/` 里 **0 处 import** → 属于开发工具，
  应移到 `devDependencies`。
- `@shadcn/react` 0.3.1：**运行时组件**，上游只被 `message-scroller.tsx` 与
  `questionnaire.tsx` 用到（聊天 / 问卷演示）→ 随演示组件删。
- 两者同为 MIT，出处同为 <https://github.com/shadcn-ui/ui>。
