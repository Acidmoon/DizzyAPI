## 三条最容易踩的坑（先记住这三条，再往下做）

### ① 上线顺序反了 = 全站 401

`keys.replace` 走 `decodeParams` + `DisallowUnknownFields`。TS 推的 key 快照带
`expiresAt` / `spendingLimitMicros` / `concurrencyLimit`，而 Go 侧 `SnapshotVersion` 仍是 **1**。
**旧 Go 二进制**会先过版本检查，再因未知字段把**整份快照拒掉** → key 缓存清空 →
**所有 API key 校验失败 → 全站 401**。

**必须先换 `bin/gatewayd`，再重启 `dizzyapi`。** 详见 [06-上线顺序.md](验收/06-上线顺序.md)。

### ② 余额快照是心跳推送的，改完余额要等

余额快照由 `quota` 插件**每 5 秒**推一轮（`pollIntervalMs: 5000`），Go 侧按 TTL 判新鲜度。
**改完余额最多等 5～10 秒再测**，否则测到的是旧快照。

心跳一断就是 2026-10-29 的生产事故：**余额已 −97，请求还在 200**。

### ③ 三条路，三种凭据，别混

| 路径 | 用什么 | 额外要求 |
|---|---|---|
| `/v1/*`、`/v1beta/*` | `Authorization: Bearer <API key>` | — |
| `/api/*` | `Cookie: dizzyapi_session=<token>` | **每个请求**都要 `X-Requested-With: dizzyapi`（登录前也要） |
| `/console/*`、`/admin/*` | 浏览器登录后的 cookie | 直连回环端口时 `Host` 必须是 `127.0.0.1:<端口>`，否则 403 |

## 一句话口径（每册里都有更细的版本）

- **费用只有一个权威来源**：`/api/usage` 的 `costMicros`。页面与它**逐字相等**才算对。
- **越权回归必须 404**：A 的会话查 B 的记录 → `404 USAGE_RECORD_NOT_FOUND`，
  **不是 403、不是空列表**（不泄露某个 reqId 是否存在）。
- **闸门三态不能含糊**：开 / 关 / 读不到。**用 `null` 冒充「关」是另一种说谎**。
- **缺服务只让对应路由 503**，入口本身照常；审计缺席时**写操作照常成功**（审计是旁路）。
