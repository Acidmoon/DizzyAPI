## 限流与计费

这一节讲两件事：**哪些请求会在到达上游之前就被拒**（限流与闸门），以及**一次请求的钱是怎么算的**（计费）。
两者都按「宁可明确拒绝，也不悄悄放行」的口径实现。

### 请求在网关里的判定顺序

每个 LLM 请求在 pre 相位按固定顺序过闸门，**任意一道返回拒绝就立刻结束，不转发上游**。
顺序本身是契约（`cmd/gatewayd` 的组装顺序 = 阶段顺序）：

| 顺序 | 闸门 | 判什么 | 拒绝时的 HTTP | 拒绝时的稳定码 |
| --- | --- | --- | --- | --- |
| 1 | key 校验 | key 是否存在、是否停用、哈希是否匹配 | 401 | `INVALID_API_KEY` |
| 2 | key 执行面 | key 是否过期、是否超出金额上限、key 并发、用户并发 | 401 / 402 / 429 | 见下 |
| 3 | 定价闸门 | 模型是否配了价格（**默认关**，打开后生效） | 403 | `MODEL_NOT_PRICED` |
| 4 | 内容审核 | 用户输入文本是否命中审核规则 | 403 | `CONTENT_BLOCKED` |
| 5 | 额度闸门 | 账户余额是否高于阈值（默认阈值 0） | 402 | `INSUFFICIENT_BALANCE` |
| 6 | 账号优先级 | 是否有可用账号（并发槽位、冷却状态） | 503 | `ALL_ACCOUNTS_SATURATED` / `ALL_ACCOUNTS_COOLING` |

闸门的**快照**（余额、价格、key 消费额、审核规则）都由 TS 侧心跳式推送、Go 侧只读缓存。
快照未就绪或过期时默认**放行**（可用性优先，后付费结算兜底），只有打开严格模式才改成拒绝，
那时返回 503 与对应的 `*_SNAPSHOT_UNAVAILABLE`。

### 并发上限：key 级与用户级

并发是**真实占位**，不是事后统计：请求进来先原子预留槽位，拿不到就立刻 429，不排队。

- **key 并发**：该 API key 同时在跑的请求数达上限 → 429 `API_KEY_CONCURRENCY_LIMIT`。
- **用户并发**：同一用户名下所有 key 的合计并发达上限 → 429 `USER_CONCURRENCY_LIMIT`。
- 两个上限都是**可选**的：没配就是不限（`null`），不是「等于 0」。
- 槽位在**响应（含整个流）写完之后**才释放；客户端中途断开也由出口统一释放，不会泄漏。

### 账号侧：并发饱和与 429 冷却

网关有多个上游账号时，选号按打分排序，并对每个账号按它自己的 `concurrency` 原子预留槽位：

- 某个账号额度用完 → 换下一个候选；**全部候选都饱和** → 503 `ALL_ACCOUNTS_SATURATED`（不排队、不放行）。
- 上游返回 429 或额度耗尽 → 该账号进入**短期冷却**（默认 30 秒），冷却期内不打分；
  **全部候选都在冷却** → 503 `ALL_ACCOUNTS_COOLING`。
- 饱和与冷却都是**不可重试**的拒因：客户端原地重试只会更糟，应当退避或换模型。

### 计费：后付费，按真实用量结算

- **不预扣、不冻结**。请求先转发，等上游返回真实 usage 之后再结算；
  所以余额允许为负（记 `overdrawn` 与扣后余额），下次请求由额度闸门拒绝。
- **金额一律整数微元**（1 元 = 1_000_000 微元），全程不经浮点。
- 价格按**每百万 token** 的单价配置，分输入 / 输出 / 缓存读 / 缓存写四档；
  费用在**读取时**按当前价格表计算，改价立刻反映在之后的用量与结算上。
- 结算**按请求幂等**：同一条用量记录（同一 `req_id`）只会扣一次，重放不会重复扣款。
- 结算失败**不推进游标**，下一轮带同一位置重放补结算；判不出的残留转人工核查
  （宁可少收一笔，绝不重复扣）。

### 计数口径：四个 token 桶

| 桶 | 含义 |
| --- | --- |
| `input` | 输入 token，**不含**缓存命中部分 |
| `output` | 输出 token（不含思考 token） |
| `cacheRead` | 缓存命中的输入 token |
| `cacheWrite` | 写入缓存的 token |

跨协议时有归一口径：Gemini 的 `promptTokenCount` **含**缓存命中，网关换算成四桶记账；
Gemini 的 `thoughtsTokenCount` 计入思考 token，**不重复**计入输出。所以对账请以
`/api/usage` 的 `costMicros` 为准，不要自己拿客户端 SDK 报的 token 数乘价格。
