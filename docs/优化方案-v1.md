## 1. 技术侦察结论（决定方案的事实）

### 1.1 新发现：27 处内联样式被 CSP 拦掉

`packages/web/src/service.ts` 的安全响应头是：

```
Content-Security-Policy: default-src 'self'; style-src 'self'; script-src 'self'; …
```

`style-src 'self'` **不放行内联样式**，所以 HTML 里写的 `style="max-width:none"`、`style="padding:16px;margin-bottom:24px"` 这类属性**浏览器直接丢弃**。实测统计：

| 文件 | 内联样式数 |
|---|---|
| `admin_redeem_codes.ts` | 3 |
| `api_docs.ts` | 9 |
| `top_up.ts` | 5 |
| `admin_audit.ts` / `admin_content_audit.ts` / `keys.ts` | 各 2 |
| `admin_observability.ts` / `admin_topup_orders.ts` / `models.ts` / `redeem.ts` | 各 1 |
| **合计** | **27** |

也就是说：**有人写「这里加个 max-width / 这里留 16px 内边距」，写了但从来没生效过。**

**第 7 条的根因已定位（`优化` 复核确认）**：`keys.ts:52` 的 `<form class="form" … style="max-width:none;margin-bottom:24px">` 这句被 CSP 丢弃，于是 `.form` 的 `max-width:520px` 一直生效；而第 53–56 行把「名称输入框」和「创建按钮」塞进**同一个 `.row`**（`.row{align-items:flex-end}`、`.row>.field{flex:1 1 200px}`），520px 里挤一行 → 就是 owner 说的「粘在一起」。**不是单纯 gap 的问题，是「结构 + 被拦的内联样式」双重原因。**

> 第 1 批必须把这 27 处**全部转成 class**，并加一条用例守住「`packages/web/src/pages/` 下不许再出现 `style="`」。

### 1.1b 字号 / 行高 / 字距的真实盘点（`优化` 实测 + `总工` 复核）

**不能只改 3 处**。实测 `packages/page-template/src/`（`assets.ts` 24 处 + `extra-styles.ts` 15 处）：

**39 处 `font-size`，9 个离散值**：`10(×1) / 11(×2) / 12(×9) / 13(×6) / 14(×12) / 16(×5) / 22(×2) / 24(×1) / 29(×1)`

| 角色 | 现在 | 放大后 | 用在哪 |
|---|---|---|---|
| micro | 10 | **12** | 徽标 / 极小字 |
| chip | 11 | **13** | 分段控件、小标签 |
| caption | 12 | **14** | 提示、表内小字 |
| label | 13 | **15** | 字段标签、表格正文 |
| body | 14 | **16** | 正文、按钮 |
| emphasis | 16 | **18** | 小标题、姓名、模型名 |
| brand | 22 | **26** | 侧栏品牌字 `.side-word` |
| title | 24 | **28** | 页面标题 `.page-title` |
| metric | 29 | **34** | 指标大数字 `.value-main` |

**注意层级错位**：`.value-main` 现在是 **29px**，标题 24px。如果只把标题涨到 28 而 metric 不动，两者就几乎一样大、层级塌掉 —— 所以 metric 必须同步涨到 **34**。

**27 处 `line-height` 硬编码 px**（`assets.ts` 18 处 + `extra-styles.ts` 9 处；值域 14/18/20/22/24/25/28/30/32/36）。
**这条最容易踩坑**：只把 `font-size` 变量化、`line-height` 留 px，用户选「特大」时正文 16→24px 却压着 22px 行高 → **文字重叠/裁切**。
→ 做法：`line-height` 一并 token 化，用**无单位行高**（如 `1.45`）让它自动跟随 `font-size`；必须保留固定值的少数几处（如 `.side-word` 的 24px）显式说明原因。

**字距只有 1 处**：`assets.ts:79` 的 `.side-word { letter-spacing: -.4px }` —— **负值，品牌字收紧是设计意图**。所以「全局 +0.01em」会被它自己覆盖、或反过来把品牌字撑开。
→ 做法：字距做成**按角色的 token**，正文/辅助 `+0.01em`，品牌保留负值。

**另有一条隐藏耦合**：`tokens.ts` 的 `METRICS.metricValueSize = 29` 被 `page-template/test/page-template.test.ts:42` **断言钉住**了。改字号必须同步改这个常量与那条断言 —— **但这是「改规格」，不是「放宽断言」**：改完要在测试里写清「字号整体上调一档」这个意图，并让断言断言新值。

**而且被钉住的只有这一个**（`总工` 独立复验）：`METRICS` 里跟文字有关的是 **7 个字号 + 5 个行高** —— `title` / `metricValue` / `metricUnit` / `label` / `caption` 五组各有 `size` + `lineHeight`，另有 `segmentedFontSize: 11`、`modelTitleSize: 16` 两个裸字号；`menuIconSize: 18` 与 `avatarSize: 32` 是**非文字尺寸**，不算字号。
**7 个字号里只有 `metricValueSize` 有断言**，其余 6 个漏改不会变红 —— 所以第 1 批必须顺手补断言。详见 §1.1d。

  第 1 批的 grep 验收断言要按 **6 处**收，否则漏网。

- `<dialog>` 全站 **0 处**、`window.confirm` **1 处**（`web/src/service.ts:50`）、`<input type="date">` **2 处**（`admin_audit.ts:122-123`）—— 与本文档一致。

### 1.1d 单一源、图表魔数与 vendor 落地（`优化` 提出，`总工` 拍板）

#### ① 字号有两个源，必须先定唯一源

`grep 'METRICS\.'` 在 `packages/page-template/src/` 里 **0 命中** —— `assets.ts` 里那 39 处 `font-size: 14px` 是**硬编码**的，跟 `METRICS` 数字相同纯靠手工同步，两者**从来没有引用关系**。所以「抽成 CSS 变量」不只是替换，得先定谁是源。

**决定：CSS 变量为唯一源。**
- `tokens.ts` 删掉 7 个字号字段与 5 个行高字段，改为导出 **`FONT_ROLES`** 单一表（9 档 × `{ size, lineHeight }`，`lineHeight` 用**无单位倍数**）；`METRICS` 只留盒模型尺寸（宽高、间距、圆角）。
- CSS 里 `:root` 定义 `--fs-<role>` / `--lh-<role>`，各处写 `font-size: var(--fs-body)`。
- **不反向**（不用 `METRICS` 插值生成 `PAGE_CSS`）：那会把 `PAGE_CSS` 从常量变成函数，`renderDocument` 的内联 `<style>` 路径跟着改，`page-template.test.ts:47-49` 那三条 `PAGE_CSS.includes(...)` 断言全要重写，改动面大于收益。
- **防漂移靠断言，不靠自觉**：新用例断言「`FONT_ROLES` 每个 role 的 size 与 CSS 里 `--fs-<role>` 的值相等」。这条断言是本次改动的**护栏**，不是可选项。

#### ② 行高用无单位数字，不用 `calc`

`line-height: 1.45` 天然等于 `1.45 × font-size`，`--font-scale` 只作用在 `font-size` 上，行高**自动跟随** —— 不需要任何 `calc`。
少数必须固定 px 的（如 `.side-word` 的 24px）要显式写注释说明原因，并加进断言的白名单。

#### ③ 图表轴宽魔数会「改完就裁」（`优化` 发现，`总工` 复验）

- `tokens.ts:161` `estimateAxisLabelWidth(text) = text.length * 7.5`，注释写死「估算 **12px** 轴标签的像素宽度」
- `charts.ts:127` 与 `charts.ts:260` **两处重复**：`Math.min(60, Math.max(22, ceil(estimateAxisLabelWidth(widestTick) + AXIS_LABEL_GAP)))`
- `.axis-text` 现在是 **12px**（`assets.ts:218`）

caption 档 12→14 后实际字宽约 8.75px/字符，公式仍按 7.5 算 → **y 轴刻度标签会被 SVG 左边界裁掉**；`Math.min(60, …)` 的上限 60 也会不够。

→ 做法：`estimateAxisLabelWidth(text, fontSize)` 改成 `text.length * fontSize * 0.625`（0.625 = 7.5/12，即每字符 0.625 em）；上限 60 / 下限 22 抽成 `AXIS_PADDING_MIN` / `AXIS_PADDING_MAX` 常量放 `tokens.ts`，**两处共用一份**（顺手消掉重复）；`AXIS_LABEL_GAP = 7` 同理按比例。

#### ④ 用户可选字号 × 服务端算图表 = 结构性冲突（决定走 B）

`paddingLeft` 是**服务端 TS** 算的，而字号要变成**用户可选**。用户选「特大」时 SVG 里的轴文字真变大了，padding 还按默认档算 → 照样裁。

**决定：方案 B —— 渲染时把当前档位传进渲染函数。**
- `renderStackedBarChart` / `renderAreaChart` 的末参改成 `options` 对象（`{ fontScale?, axisFontSize? }`），默认 `1`。
- 生产只有一个调用点（`web/src/pages/usage.ts:73`），`web` 从当前用户偏好读档位传进去；其余全是测试。
- 不选 A（图表轴文字固定不跟随）：用户改了字号、图表不跟着变，观感是「只改了一半」。

#### ⑤ vendor 落地：`jsHref` 必须扩成有序数组

`shell.ts:82-85` 的 `assets` 是 `{ cssHref, jsHref? }`，`shell.ts:149-151` 只吐**一个** `<script src>`。htmx / Tom Select / flatpickr / Floating UI 必须**在 `app.js` 之前按顺序**加载。

- **CSS 不改签名**：`web` 现在就是 `PAGE_CSS + COMPONENT_CSS + fontCss` 拼接，vendor CSS 照样拼进去。
- **JS 改签名**：`jsHref?: string` → `jsHrefs?: readonly string[]`（按数组顺序输出 `<script src>`，`app.js` 排最后）。**不保留旧字段** —— 只有 `web` 一个消费者，留两份源必然漂移。`page-template.test.ts:69` 与 `:72` 两条断言同步改。
- **不拼成一个大 blob**：每个库要保留自己的 `LICENSE` 归属与独立缓存头。

#### ⑥ 我补的一条真风险：CSP 会不会拦 vendor 库的内联样式

`packages/web/src/service.ts:41` 的 CSP 是 `style-src 'self'`，**没有 `'unsafe-inline'`、也没有 nonce**。而：
- CSSOM 赋值（`el.style.top = '10px'`、`el.style.cssText = …`）**不受 CSP 限制**
- `el.setAttribute('style', '…')` 与动态注入 `<style>` **受限制，会被拦**

flatpickr 的浮层定位、Tom Select 的宽度同步都可能走 `style` 属性。**一旦被拦，浮层会跑到页面左上角** —— 这不是「样式差一点」，是控件直接不可用。而 `style-src-attr` **没有 nonce 机制**（nonce 只对 `<style>` / `<script>` 元素有效），所以「加 nonce」救不了这条路。

→ **第 1 批开工第一步是 spike（半天内）**：4 个库都挂到真页面上、开真 CSP，用浏览器实测下拉浮层、日历浮层、tooltip 定位是否正常。
- 全正常 → 继续。
- 有被拦 → **绝不加 `'unsafe-inline'`**（那等于把全站 CSP 拆掉）。两条退路：① 在 vendor 的那一份里把 `setAttribute('style', …)` 改成 CSSOM 赋值（一行级补丁，`LICENSE` 允许改造，改动要在报告里列出）；② 换库。**结论必须带实测证据回来，不许拍脑袋。**

#### ⑦ `packages/deepseek-usage` 是 `page-template` 的整份重复副本

自带 `tokens.ts` / `render.ts` / `client.ts`，同样有 7.5 魔数、同样 `.axis-text 12px`。它是**已禁用**的像素参考，第 1 批**不动它** —— 但要写进 `AGENTS.md` 的已知重复，别以为改了 `page-template` 它也变。

### 1.2 控件的真实边界（决定「用现成的」能用哪些）

| 原控件 | 能不能被 CSS 改造 | 结论 |
|---|---|---|
| `<dialog>`（原生模态元素） | **能**，它没有任何默认外观，只提供焦点陷阱 / ESC / backdrop | **留用**，行为别自己写 |
| `<input type=text>` / `<button>` / `<input type=checkbox>` | 能（checkbox 要靠 `appearance:none` + 自绘标记） | 留用 |
| `<select>` 的**下拉浮层** | **不能**（浮层由浏览器绘制，CSS 管不到） | **必须换库** |
| `<input type=date>` 的**日历浮层** | **不能** | **必须换库** |
| `window.confirm()` | **不能**（原生模态，不可样式化） | **必须换** |
| 柱状图 hover 提示（现在用 SVG `<title>`） | 不能 | **自绘 tooltip** |

**给 owner 的判断依据**：你说的「不准用浏览器默认控件」，准确说是这 4 类**浮层由浏览器绘制、CSS 碰不到**的玩意儿。`<dialog>`/`<input>`/`<button>` 是语义元素、外观完全由我们 CSS 决定，不算「默认控件」——用它们不是偷懒，是把焦点陷阱、无障碍、ESC 这些**容易写错的东西交给浏览器**。

### 1.3 现成库选型（owner 要求「别自研，用现成」）

全部满足三条硬约束：**① 无构建步骤（直接 `<script>` 引入）② 可 vendor 到本地（CSP 是 `'self'`，不能走 CDN）③ 许可证干净**。

| 用途 | 选型 | 许可证 | 体积 | 为什么选它 |
|---|---|---|---|---|
| **局部刷新 / 部分页渲染 / 弹窗取内容** | **htmx 2.x** | **Zero-Clause BSD**（最宽松，等同公有领域） | ~14 KB | 它就是这个问题的标准答案：`hx-boost` 让所有链接表单走 AJAX，`hx-target` 指定只换主列，`hx-push-url` 接管地址栏，**无 JS 时自动退化为整页跳转**——正好是第 4 条要的形态，不用自己写一行路由代码。它的文档里还有和 Tom Select 配合的官方示例 |
| **下拉 / 多选** | **Tom Select** | **Apache-2.0** | ~16 KB gzip | 无依赖、框架无关、键盘导航原生手感，`selectize.js` 的正统后继。需 vendor `LICENSE`（Apache-2.0 要求保留版权声明） |
| **日期选择** | **flatpickr** | **MIT** | ~40 KB | 零依赖、主题可换、可直接吃我们现有的 `<input type=date>` 值 |
| **提示气泡定位** | **Floating UI** | **MIT** | ~3 KB（按需） | 只算坐标不画样式，样式我们全权控制 |
| **模态外壳** | 原生 `<dialog>` | — | 0 | 见 §1.2：留用元素，CSS 全自绘 |

**不选 Shoelace / Web Awesome 的理由**（免得以后再讨论一遍）：那一类 Web Components 组件库会自带一整套设计语言与主题变量，我们的视觉 token 已经在 `page-template` 里定好了，接进来等于打两套设计系统，改造成本高于收益；而且它靠 Shadow DOM 注入样式，与我们「CSP 全 'self' + 单一 CSS 文件」的模型冲突。

**许可证纪律核对**：0BSD / MIT / Apache-2.0 **都不是** AGPL / LGPL，可以 vendor。vendor 时每个库要带自己的 `LICENSE` 文件（Apache-2.0 还必须保留版权声明），放在 `packages/page-template/assets/vendor/<name>/`。

### 1.4 Markdown 业界做法（owner 要求「看别人的 api 文档怎么实现」）

查了 Mintlify（[concepts](https://www.mintlify.com/docs/reference/concepts)、[markdown-export](https://www.mintlify.com/docs/ai/markdown-export)）与 [llms.txt 规范 v2](https://llmstxt.org/)（Jeremy Howard 提的，已被 Mintlify / GitBook / Docusaurus / VitePress 插件支持，**OpenAI、Anthropic、Gemini 官方 API 文档都发 `llms.txt`**）：

业界现在的事实标准是**三件套**，不是「一个网页里塞 markdown」：

1. **内容源是真 `.md` 文件**，不是硬编码 TS 常量（我们现在是后者，465 行）
2. **页面用 Markdown 渲染成 HTML**（服务端渲染即可）
3. **同时提供机器友好的副本**：
   - `GET /llms.txt` —— 站点级索引，告诉 agent「有哪些文档、去哪拿干净的 markdown」
   - `GET <页面路径>.md` —— 每个页面旁边放一份纯 markdown，agent 直接抓
   - HTML 里加 `<link rel="alternate" type="text/markdown" href="…md">`，和 `rel="describedby"` 指向 `llms.txt`

**这正好就是第 5 条「用户可以复制一整页方便投喂给 agent」的正解**：与其做「复制按钮」，不如**让 URL 本身就是 markdown**（`/console/api-docs.md`），再配一个复制按钮复制它。agent 直接抓 URL，人也可以点。

**渲染器选型**：**markdown-it**（MIT，已核 LICENSE）。理由：服务端渲染、无客户端依赖、CSP 不用放开、可关闭 HTML 直通（`html: false` 把内嵌 HTML 当纯文本，天然防 XSS，不用再引 sanitizer）。

### 1.5 CLI 现状（owner 说这是项目重心之一）

**现在一行都没有**：`cmd/` 下只有 `cmd/gatewayd`，29 个包都没有 `bin` 字段，也没有任何插件注册 cordis 子命令。

CLI 要能用，得先看清两条鉴权路径（它们**不一样**，这是设计的关键）：

| 路径 | 鉴权 | 备注 |
|---|---|---|
| `POST /v1/*`（模型请求） | `Authorization: Bearer <API key>` | Go gatewayd 直接校验 key 哈希快照 |
| `GET/POST /api/*`（控制面） | **HttpOnly 会话 cookie** + 必须带 `X-Requested-With: dizzyapi` | 会话**不进 JSON、不进 URL**（`api` 插件硬约束） |

所以 CLI 有两种形态可选，我推荐 A：

| | A. **独立 Go 二进制 `cmd/dizzy`**（推荐） | B. TS 包 `packages/cli` + `bin` |
|---|---|---|
| 用户装什么 | 一个静态二进制，**不需要 Node** | 需要 Node 26 + pnpm |
| 复用 | 复用 `contracts` 的类型与错误码 | 复用 TS 侧服务接口（但 CLI 是外部进程，用不上） |
| 交叉编译 | 已有现成流程（`GOOS=linux go build`） | 要打包 |
| agent 可用性 | 高（一行 `curl` 换成一个二进制） | 低（要先有 node 环境） |
| 成本 | 中（要自己写 HTTP client 与 cookie 罐） | 低 |

推荐 **A**：因为 CLI 的用户是「agent 与开发者」，他们的机器上不一定有 Node；而我们的部署机本来就有 Go 交叉编译流程。

**CLI 的命令骨架（第一批）**：

```
dizzy login --base https://api.example.com     # 存会话到 ~/.dizzy/credentials.json（0600）
dizzy chat -m deepseek-flash "你好" --stream         # 打 /v1/chat/completions，打印 token 与花费
dizzy models                                         # 打 /api/models
dizzy usage [--today|--7d] [--by model|key]          # 打 /api/usage
dizzy keys list|create|rotate|disable                # 打 /api/keys
```

|---|---|
| 归属 | **per-user**（每个用户自己看自己的），不是全局设置 |
| 存哪 | `user` 表新列 `ui_preferences TEXT`（JSON），`user` 插件是唯一写者。**「一个数据一个写者」**：不加新插件，也不动 `settings` 插件（那是全局配置） |
| 可调项 | `fontScale`（0.875~1.5 四档预设，不放开任意值——否则布局会炸）、`letterSpacing`（0 / 0.01em / 0.02em）、`navOrder`（第 4 批用） |
| 怎么生效 | web 输出 `/assets/theme.css`（`private, no-store`），把 §1.1b 全部 **9 个字号变量 + 行高 + 字距**按 `fontScale` 重算后覆盖到 `:root`。**不走内联样式**（CSP 会拦，§1.1 的教训）。因为行高已改成无单位，缩放时自动跟随，不会重叠 |
| 图表怎么办 | **theme.css 管不到 SVG 里的几何**：图表 `paddingLeft` 是服务端算的。所以同一份 `fontScale` 还要**传进图表渲染函数**（§1.1d④），否则用户调大字号后轴标签会被裁。这是本方案唯一「设置值必须同时进渲染层」的地方 |
| 在哪儿改 | 个人资料页 `/console/profile` 加「界面偏好」区块：字号四档、字距三档，保存后立即生效 |
| 默认 | 就用你要求的「大两号」（见 §1.1b 的 9 档表），即 `fontScale = 1.0` 对应新基准。也就是说**全站默认已经是放大后的**，用户想再调才调 |
| 管理员视角 | 管理台也生效（同一个用户偏好） |

### 4.2 CLI 是重心（第 13 条升级）

按 §1.5 的 A 方案做**独立 Go 二进制**，单独第 5 批，不与 UI 混。理由：
- **agent 是 CLI 的第一用户**——agent 要调你的网关做开发调试，要求「零环境依赖、一条命令能跑」，Go 静态二进制最符合
- CLI 进 `AGENTS.md` 与 `llms.txt`，让 agent 知道怎么用
- 后续可以延伸：`dizzy chat --json` 给 agent 机器可读输出、`dizzy bench` 压测、`dizzy tail` 实时看请求

### 4.3 Markdown 按业界做（第 5 条升级）

见 §1.4 的「三件套」：真 `.md` 源 + Markdown 渲染 + `llms.txt` / `.md` 副本。**这不是「加个复制按钮」，是让整个文档站点对 agent 友好。**

### 4.4 计划落成文档并指明「谁、怎么做」

本文件即是。每条要求 → 谁做 → 怎么做 → 怎么验收，见 §3 各批表格与 §5 索引表。

## 6. 上线纪律（写进 AGENTS.md）

**已由 `总工` 拍板的技术决定**（不是产品取舍，有异议随时推翻）：

| 编号 | 决定 | 理由 |
|---|---|---|
| §1.1d① | 字号**单一源 = CSS 变量**，`METRICS` 删字号/行高字段，`FONT_ROLES` 表 + 一致性断言守漂移 | 反向生成 `PAGE_CSS` 要重写 3 条现有断言，改动面大于收益 |
| §1.1d② | 行高**全部改无单位数字** | 自动跟随 `font-size`，零 `calc`，用户选「特大」不重叠 |
| §1.1d③ | 图表轴宽 `7.5` 改由字号派生（`0.625 em/字符`），上下限抽常量、两处重复合一 | 否则字号一放大，y 轴刻度必被裁 |
| §1.1d④ | **图表轴文字跟随用户字号**（方案 B，`fontScale` 传进渲染函数） | 唯一生产调用点，代价小；不跟随会显得「只改了一半」 |
| §1.1d⑤ | `jsHref` → 有序 `jsHrefs` 数组，`app.js` 排最后，不保留旧字段 | vendor 库必须按序加载；只有一个消费者，不留双源 |
| §1.1d⑥ | CSP 不放宽；先 spike 实测，被拦就改 vendor 的 `setAttribute('style')` 为 CSSOM 赋值或换库 | 加 `'unsafe-inline'` 等于拆掉全站 CSP；`style-src-attr` 没有 nonce 可用 |
